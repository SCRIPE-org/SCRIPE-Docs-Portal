How does SCRIPE Data Exchange Studio Deliver MENA Normalization, Streaming Excel Imports, and Partial Commits?

Long image

A

Answer

SCRIPE Data Exchange Studio unifies enterprise spreadsheet imports, exports, and background execution across CRM, PartyKernel, and Identity modules. It pairs a compact 1-button Data Exchange dropdown, a 4-step Next.js 16 wizard with live normalization preview, a 3-route Admin data-transfer module, and an AstraFlow 2.3.0 streaming engine.1

  1. The backend OwaspSpreadsheetSecurityValidator verifies magic bytes, blocks ZIP bombs, neutralizes formula payloads, and locks audit timestamps as ExportOnly via IsImportDeniedField.2
  2. SpreadsheetValueNormalizer runs deterministic O(n) MENA and enterprise transforms with zero user regexes, while ColumnNormalizationPopover renders live Raw -> Normalized previews in Step 2.3
  3. DataTransferImmediateWorker dispatches via Channel<Guid>, applies .IgnoreQueryFilters() before DataExchangeAmbientContext.Begin(snapshot), and handles DbUpdateConcurrencyException safely on concurrent cancellation.4
  4. GenericCrudView pages mount one compact @core/ui/dropdown-menu Data Exchange trigger inside CrmSectionHeader, while /admin/data-exchange provides 3 dedicated GenericCrudView<T> routes.5

How does the O(n) MENA & Enterprise Normalization Engine standardize spreadsheet data safely?

Every spreadsheet cell flows through deterministic linear-time normalization before type parsing or provider persistence. Neither backend C# nor frontend TypeScript accepts user-supplied regular expressions, eliminating ReDoS risks across untrusted uploads.3

Both DataExchangeTransformRule in Core.Application and previewNormalizedSample in mapping-validation.ts share identical 17-option semantics. Operators configure rules inside ColumnNormalizationPopover during Step 2 and inspect Raw -> Normalized outputs live before submitting dry-run jobs.7
