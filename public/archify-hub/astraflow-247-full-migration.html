What does the AstraFlow 2.4.7 migration cover?

Long image

A

Answer

SCRIPE’s backend now uses the AstraFlow 2.4.7 family on .NET 10, across all 16 packages where each package has an applicable role.

  1. Central package management pins every family package to 2.4.7.
  2. Application projects use AstraFlow mediator, generated mappings, validation, security, and data projection.
  3. Test projects use AstraFlow assertions and test helpers; the legacy assertions package is gone.
  4. The local AstraFlow CLI is installed and pinned at 2.4.7.

How does an Identity permission list use generated projection?

The handler filters the read-only query before projection, then encrypts identifiers after the database projection.3

Diagram structure
  • Query handler handler
  • Permission repository store
  • Projection registry mapping
  • Secure ID encryption codec
  • handler → store · AsNoTracking query with filters
  • store → mapping · ProjectWith PermissionResponse
  • mapping → codec · Projected response rows
  • codec → handler · Encrypted permission identifiers

This keeps filtering and column selection in the provider query. The response retains SCRIPE’s encrypted-ID contract.3

3

How does DataTransfer keep its Oracle model aligned?

Oracle’s EF Core provider does not support filtered indexes. SCRIPE clears EF’s nullable unique-index filter only in the Oracle DataTransfer context. Oracle’s native unique index permits multiple tenantless keys, so this keeps the model portable without a schema change.4

What remains for the AstraFlow team?

The source-omission enhancement is recorded in the AstraFlow standby thread. The 2.4.7 convention API has no source-member omission allowlist.6

SCRIPE keeps convention StrictMode=false so intentional DTO omissions do not block startup. Findings remain visible and sensitive-member denial stays enabled. AstraFlow triage classified this as a non-blocking enhancement; SCRIPE can continue on 2.4.7 without waiting for a patch.

The CRM refusal coverage gap is closed with real no-permission handler assertions and an inventory mapping for all 26 CRM handlers. It did not identify an AstraFlow package defect.7

Non-blocking framework reports

No AstraFlow hotfix is required to continue this migration on 2.4.7.
