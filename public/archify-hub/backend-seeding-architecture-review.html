How does SCRIPE separate production and development seeding, and where are the gaps?

Long image

A

Answer

Yes: SCRIPE separates production baseline seeders (DatabaseSeeder and 18 IModuleSeeder implementations) from opt-in development UAT seeders (DevDataSeederRunner and 19 IModuleDevDataSeeder implementations) across all 19 modules.

  1. Production baseline seeders sync permissions, menus, features, editions, compliance rules, and system roles idempotently.1
  2. Production web hosts disable startup seeding (SeedDatabase:Enabled: false), while scripe db seed runs --seed and exits before Kestrel starts.2
  3. Development UAT seeders stay opt-in (SeedDatabase:SeedDevData: false) and run in strict Order (10 to 170) via deterministic UUID v4 IDs.3
  4. Audit uncovered 8 gaps, led by missing production environment guards on --seed-dev and double execution of 3 hosted seeders.4

How do startup and CLI seeding execute end to end?

Diagram structure
  • Init schemas schema-init
  • Seed enabled? cli-check
  • Set SeedingScope scope-begin
  • Sync Identity core core-sync
  • Run 18 modules module-seeders
  • Dev opt-in? dev-gate
  • Run 19 dev DAG dev-runner
  • Serve or exit host-exit
  • cli-check → scope-begin · yes
  • core-sync → module-seeders · next
  • dev-gate → dev-runner · yes
  • dev-gate → host-exit · no
  • dev-runner → host-exit · done
  • module-seeders → dev-gate · done
  • schema-init → cli-check · ready
  • scope-begin → core-sync · quiet

Program.cs ensures schemas exist first, runs CLI seed mode if --seed is present, and otherwise starts DatabaseSeeder as a hosted service.5

  1. Init schemas ↗

    InitializeDatabaseSchemasAsync() creates module schemas and outbox or inbox tables before Kestrel or seeding runs.

  2. Seed enabled? ↗

    ExecuteCliSeedModeAsync intercepts --seed before Kestrel; normal boot skips seeding when SeedDatabase:Enabled is false.

  3. Set SeedingScope ↗

    SeedingScope.Begin() sets AsyncLocal<bool> so BaseDbContext and AuditableEntityInterceptor suppress outbox and audit floods.

  4. Sync Identity core ↗

    DatabaseSeeder migrates Identity and runs Guardian triggers, Permissions, Roles, Admin, Workspaces, Menus, Themes, and Presets.

  5. Run 18 modules ↗

    RunModuleSeedersAsync executes registered IModuleSeeder instances sorted by Order to migrate schemas and seed baseline catalogs.

  6. Dev opt-in? ↗

    RunDevSeedersIfRequestedAsync checks --seed-dev or SeedDatabase:SeedDevData; missing IsProduction() checks are an audit gap.

  7. Run 19 dev DAG ↗

    DevDataSeederRunner runs all 19 dev seeders from Order 10 to 170 using deterministic UUID v4 IDs from DevSeedConstants.

How do production and development seeders differ?

SCRIPE uses two separate DI contracts so baseline catalog sync stays isolated from multi-tenant demo personas and sample transactions.1

DimensionProduction Baseline (IModuleSeeder)Development UAT (IModuleDevDataSeeder)
Master orchestratorDatabaseSeeder (IHostedService)DevDataSeederRunner (Singleton)
Default on local web bootRuns (SeedDatabase:Enabled: true)Opt-inSkipped (SeedDevData: false)
Default in Production configDisabled (appsettings.Production.json)UnprotectedDisabled, but lacks runtime block
CLI commandscripe db seed (--seed)scripe db seed --dev (--seed-dev)
Execution scopeSeedingScope suppresses outbox and auditSeedingScope suppresses outbox and audit
Failure propagationSwallowsLogs error and exits 0Fail-fastLogs error and rethrows exception
Cross-module ID strategyNatural keys (Code, Slug, Key)Deterministic UUID v4 in DevSeedConstants

Production seeders apply four distinct strategies rather than a single insert-once pattern.6

Production strategyConcrete seedersBehavior on repeat startup
Smart sync (upsert)PermissionSeeder, WorkspaceSeeder, MenuItemSeeder, MessageTemplateSeeder, PlatformOptionSetSeeder, Compliance seedersInserts missing rows and updates changed metadata; keeps IsSystem = false items
Self-healing + SEC-10RoleAndAdminSeeder, EnsureTenantDomainsAsync, CrmPipelineSeeder, CrmSettingsSeederRestores SYSTEM_SUPER_ADMIN, superadmin, and tenant subdomains; fails closed in non-Development if password unset
DDL guardian triggersGuardianTriggerSeeder (Oracle, PostgreSQL, SQL Server, SQLite/MySQL)Runs CREATE OR REPLACE triggers blocking raw SQL deletion of system roles and superadmin
Seed-once (SeedIfEmptyAsync)LoginThemeSeeder, DashboardPresetSeeder, AppCategorySeeder, EditionSeeder, FeatureSeeder, Onboarding seedersInserts only when missing so admin edits and deletions stay intact
